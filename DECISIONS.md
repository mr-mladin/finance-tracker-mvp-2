# DECISIONS: Finance Tracker MVP 2

## Контекст

`START.md` - основной файл входа в проект.
`AGENTS.md` - правила работы Codex в репозитории.
`TODO.md` - ближайшие задачи без длинной истории.
`HISTORY.md` - архив старого подробного handoff, читать только по необходимости.
`HANDOFF.md` - короткая подсказка, не длинный журнал.

## Продукт

- Не делать лендинг. Первый экран всегда должен быть рабочим финансовым трекером.
- Интерфейс должен быть пригоден для ежедневного использования: плотный, понятный, без маркетинговой воды.
- Демо-данные пока живут в `localStorage`; Supabase подключать отдельным этапом.

## Дизайн

- Направление: чистый светлый Liquid Glass / Claude-like.
- Карточки спокойные, белые, с мягкими границами.
- Основной акцент зелёный.
- Эмоджи пользователю нравятся; не заменять их на сухие иконки без причины.
- Не добавлять декоративные орбы, тяжёлые градиенты и лендинговую композицию.

## Навигация

- Desktop: счета слева, рабочая область справа.
- Узкий viewport: меню сверху как компактная sticky-панель, список счетов скрыт.
- Выбор счета не должен переключать вкладку: если пользователь в `Отчёт`, он должен остаться в `Отчёт`.

## Dashboard Layout

- Dashboard нельзя строить как простой swap трёх блоков.
- Текущая модель: две независимые колонки (`column`, `columnOrder`) плюс wide/full блоки.
- Пользователь должен свободно класть блок `Операции` под `Доходы и Расходы`, не сдвигая `Динамика и планы`.
- Во время drag preview должен быть обратимым: если блок возвращён на исходное место до отпускания, соседний блок возвращается назад.

## Счета и группы

- Удаление группы не должно удалять счета.
- Безопасное удаление группы: убрать group record, очистить `groupId` у счетов, операции не трогать.
- Если группа есть, её можно удалить из `Настройки -> Данные`, это важно для узкого viewport.

## Контекст Для Агентов

- Не раздувать `START.md`.
- В историю переносить только крупные вехи.
- Перед визуальными правками смотреть страницу в браузере, не править вслепую.
- Новый чат должен начинать с `START.md`, а не с чтения всего проекта.
- Один завершённый этап работы фиксировать git-коммитом.
